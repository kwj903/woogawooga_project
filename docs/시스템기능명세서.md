# 보이스피싱 판단 AI 모델 개발 및 외부 시스템 활용을 위한 API 개발
## 시스템 기능 명세서

### 문서 정보
- **문서명**: 시스템 기능 명세서
- **작성자**: 우가우가조 (곽우재, 김채연, 송진주, 정영재)
- **작성일**: 2025.07.31
- **버전**: v4.0 (최종 구현 사항 반영)
- **프로젝트명**: 보이스피싱 판단 AI 모델 개발 및 외부 시스템 활용을 위한 API 개발
## 1. 최종 제품 개요
본 시스템은 Django 4.x + Django Channels 기반의 웹 애플리케이션으로 구현된 보이스피싱 판별 서비스입니다. SPA 방식으로 구현되어 사용자가 음성 파일을 업로드하면 5단계 AI 파이프라인(STT → 텍스트 전처리 → 1차 ML → 2차 DL → LLM)을 통해 보이스피싱 여부를 판별하고 WebSocket을 통해 실시간으로 진행 상황을 업데이트합니다.
### 1.1 기술 스택
| 구분 | 기술 | 설명 |
|------|------|------|
| 백엔드 | Django 4.x + Django Channels | 웹 애플리케이션 프레임워크 + WebSocket 지원 |
| 프론트엔드 | HTML5, CSS3, JavaScript (ES6+) | SPA 구조, 반응형 디자인, WebSocket 클라이언트 |
| 데이터베이스 | MySQL | 운영 데이터베이스 (환경변수 설정) |
| AI/ML 모델 | Stacking Classifier + PyTorch Ensemble + GPT-4o | 5단계 분석 파이프라인 |
| STT 서비스 | VITO API | 한국어 음성-텍스트 변환 |
| 텍스트 전처리 | KiWi (Korean in Willow) | 형태소 분석 및 토큰화 |
| 실시간 통신 | Django Channels (WebSocket) | 분석 진행률 실시간 업데이트 |
| 로깅 시스템 | Python logging + 파일/DB 저장 | 포괄적 모니터링 |

## 2. 핵심 시스템 기능 명세
### 2.1 5단계 분석 파이프라인
| 단계 | 기능 | 설명 | 구현 기술 | 상태 |
|------|------|------|-----------|------|
| 1단계 | STT 변환 | 음성 파일을 텍스트로 변환 | VITO API | ✓ |
| 2단계 | 텍스트 전처리 | 형태소 분석 및 토큰화 | KiWi (Korean in Willow) | ✓ |
| 3단계 | 1차 ML 분석 | 키워드 기반 초기 분류 (임계값 0.5) | Stacking Classifier | ✓ |
| 4단계 | 2차 DL 분석 | 보류 케이스 정밀 분류 | PyTorch Ensemble | ✓ |
| 5단계 | LLM 설명 생성 | 사용자 친화적 설명 생성 | GPT-4o API | ✓ |
### 2.2 주요 기능 상세 명세

| ID | 기능명 | 설명 | 우선순위 | 구현여부 |
|----|--------|------|----------|----------|

| FC-01 | 파일 업로드 및 검증 | **목적**: 드래그앤드롭/파일선택을 통한 음성 파일 업로드 및 검증<br>**동작 흐름**: 파일 선택 → 크기/형식 검증 → 서버 업로드 → 메타데이터 저장<br>**입력**: AMR, MP3, WAV, M4A (최대 50MB)<br>**출력**: 업로드 성공/실패, 파일 ID<br>**구현**: HTML5 File API, Django FileField | 상 | ✓ |
| FC-02 | VITO STT 변환 | **목적**: 한국어 음성을 고정밀도로 텍스트 변환<br>**동작 흐름**: 음성 파일 → VITO API 전송 → 토큰 관리 → 폴링 결과 확인 → 전사 텍스트<br>**입력**: 음성 파일 (지원 포맷)<br>**출력**: 전사된 텍스트<br>**구현**: VITO REST API, 비동기 처리 | 상 | ✓ |
| FC-03 | KiWi 텍스트 전처리 | **목적**: STT 결과를 ML/DL 모델 입력용으로 전처리<br>**동작 흐름**: 전사 텍스트 → KiWi 형태소 분석 → NNG, NNP, VV, VA 추출 → 토큰화<br>**입력**: STT 전사 텍스트<br>**출력**: 전처리된 토큰 리스트<br>**구현**: KiWi 라이브러리 | 상 | ✓ |
| FC-04 | 1차 ML 분석 | **목적**: Stacking 앙상블로 빠른 초기 분류<br>**동작 흐름**: 전처리 텍스트 → TF-IDF 벡터화 → Stacking Classifier → 임계값 기반 분류<br>**입력**: 전처리된 텍스트 토큰<br>**출력**: 예측 확률, 분류 결과 ('0': 정상, '1': 피싱, '보류': 애매)<br>**구현**: scikit-learn, joblib | 상 | ✓ |
| FC-05 | 2차 DL 분석 | **목적**: 보류 케이스에 대한 PyTorch 앙상블 정밀 분석<br>**동작 흐름**: 보류 텍스트 → 토큰화 → Ensemble 모델 → 가중 평균 → 최종 분류<br>**입력**: 1차 모델 보류 케이스<br>**출력**: 최종 예측 확률, 보이스피싱 여부<br>**구현**: PyTorch, Transformers | 상 | ✓ |
| FC-06 | GPT-4o 설명 생성 | **목적**: 피싱 유형 분류 및 사용자 친화적 경고 메시지 생성<br>**동작 흐름**: 판정 결과 → GPT-4o API 호출 → 유형 분석 → 경고 메시지 생성<br>**입력**: 분석 대상 전사 텍스트 + 모델 결과<br>**출력**: 피싱 유형, 상세 설명, 대응 방법<br>**구현**: OpenAI GPT-4o API | 상 | ✓ |
| FC-07 | SPA 웹 인터페이스 | **목적**: 단일 페이지에서 완전한 사용자 경험 제공<br>**동작 흐름**: 업로드 → 실시간 진행률 표시 → 결과 표시 → 피드백 수집<br>**화면 구성**: 업로드/진행/결과/오류 화면 통합, 반응형 디자인<br>**구현**: HTML5, CSS3, JavaScript ES6+, WebSocket 클라이언트 | 상 | ✓ |
| FC-08 | WebSocket 실시간 통신 | **목적**: 분석 진행 상황 실시간 업데이트<br>**동작 흐름**: WebSocket 연결 → 각 단계별 진행률 전송 → 프론트엔드 업데이트<br>**구현**: Django Channels, WebSocket | 상 | ✓ |
| FC-09 | 사용자 피드백 시스템 | **목적**: 분석 결과 정확도 평가 및 의견 수집<br>**동작 흐름**: 정확도 평가(정확함/부정확함) → 의견 입력 → DB 저장<br>**구현**: REST API, UTF-8 인코딩 보장 | 중 | ✓ |

| SPA-03 | 결과 화면 | / (동일 페이지) | 분석 결과 표시 및 피드백 수집 | 최종 판별 결과, 피싱 유형, 경고 메시지, 피드백 폼, 재분석 버튼 | 결과 표시, 피드백 수집, 재분석 옵션 |
| SPA-04 | 오류 화면 | / (동일 페이지) | 분석 실패 시 오류 표시 및 복구 옵션 | 상세 오류 메시지, 재시도 버튼, 새 파일 업로드 버튼 | 오류 안내, 재시도, 새 파일 선택 |
| UI-05 | 통계 페이지 | /statistics/ | 시스템 사용 통계 대시보드 | 총 분석 건수, 피싱 탐지 건수, 정상 통화 건수, 탐지율 | 통계 정보 표시, 성능 모니터링 |
| UI-06 | 분석 진행 페이지 | /analysis/ | 별도 분석 진행 페이지 (선택적) | 단계별 진행 표시, 작업 ID 표시 | 분석 진행 상황 모니터링 |
| UI-07 | 결과 페이지 | /result/ | 별도 결과 페이지 (선택적) | 결과 뱃지, 피싱 유형, 신뢰도, 경고 메시지, 피드백 폼 | 결과 상세 표시, 피드백 제출 |

### 6.2 SPA 화면 전환 흐름
1. **업로드 화면** → 파일 선택 및 분석 시작
2. **분석 진행 화면** → WebSocket을 통한 실시간 진행률 표시 (STT → 전처리 → 1차ML → 2차DL → LLM)
3. **결과 화면** → 최종 판별 결과 표시 및 피드백 수집
4. **오류 화면** → 오류 발생 시 복구 옵션 제공

### 6.3 반응형 디자인
- **데스크톱**: 1200px 이상, 전체 기능 지원
- **태블릿**: 768px-1199px, 최적화된 레이아웃
- **모바일**: 767px 이하, 터치 최적화 인터페이스
## 7. 제약사항 및 한계

### 7.1 파일 및 시스템 제약
- **파일 크기 제한**: 최대 50MB (음성 파일 기준)
- **지원 파일 형식**: AMR, MP3, WAV, M4A
- **실시간 통화 분석 미지원**: 파일 업로드 방식만 지원
- **브라우저 호환성**: Chrome, Firefox, Safari, Edge 최신 버전

### 7.2 외부 API 의존성
- **VITO API**: STT 변환을 위한 필수 서비스, API 토큰 필요
- **GPT-4o API**: LLM 설명 생성을 위한 필수 서비스
- **API 장애 시**: 백업 전략으로 목업 데이터 활용

### 7.3 성능 및 확장성 제약
- **동시 처리 제한**: 서버 리소스에 따른 동시 분석 요청 수 제한
- **데이터베이스**: MySQL 연결 풀 관리 필요
- **모델 로딩**: 앱 시작 시 ML/DL 모델 초기화 시간 소요

## 8. 시스템 아키텍처 및 배포

### 8.1 핵심 아키텍처
- **백엔드**: Django 4.x + Django Channels (WebSocket 지원)
- **데이터베이스**: MySQL (환경변수 설정)
- **외부 API**: VITO API + GPT-4o API 연동
- **파일 관리**: media/uploads/ 디렉토리
- **로깅**: 파일/DB/콘솔 다중 핸들러

### 8.2 환경 설정
- **환경변수**: .env 파일로 API 키 및 DB 정보 관리
- **로깅 설정**: logs/woogawooga.log 파일 로깅
- **채널 레이어**: InMemoryChannelLayer (개발용)

### 8.3 디자인 특징
- **반응형 웹 디자인**: 모바일/태블릿/데스크톱 최적화
- **SPA 구조**: 페이지 전환 없는 단일 페이지 애플리케이션
