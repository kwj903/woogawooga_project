4. LLM 기반 데이터 확장 결과 분석

4.1. 데이터 생성 

4.1.1. 생성 목표 및 프롬프트 설계
데이터 생성의 최종 목표는 음성 피싱 탐지 모델 학습에 적합한 다양성과 규모를 갖춘 시나리오 데이터셋을 구축하는 것. 이를 위해 다음과 같은 세부 목표를 수립.
●	총 1300개(기관사칭 40, 대출빙자 20, 메신저 피싱 20, 택배사칭 20 등) 대화를 4가지 유형으로 분산 생성
●	각 대화마다 문장 수 제약(3~10문장 또는 8~12문장, 13~15문장)을 두어 모델이 다양한 길이의 대화 패턴을 학습
●	고정된 이름 ‘OOO’와 CSV 형식을 통해 후처리 파이프라인에서 쉽고 일관되게 레이블링 및 병합
●	기존 CSV와 병합 시 중복 제거 로직을 적용하여 데이터 품질 보장
●	배치 크기(batch_size)를 5로 설정하고, start_index를 동적으로 할당해 파일명(phishing_001~)을 순차적으로 부여
프롬프트 설계는 크게 두 가지 단계.
1.	시스템 프롬프트 설정: 대화의 구조와 제약을 고정한 ‘규칙 책자’ 역할
2.	사용자 프롬프트 전달: 현재 배치에서 생성할 대화 개수, 시작 파일번호, 시나리오 유형을 변수로 주입
이러한 구조를 통해, 매 회 OpenAI API를 호출할 때마다 일관된 제약을 유지하면서도 배치별 다양한 조건을 유연하게 반영할 수 있습니다.

 
4.1.2. 프롬프트 엔지니어링 
시스템 프롬프트는 "15년 경력의 금융 범죄 수사 전문가이자 음성 피싱 탐지 시스템 개발자"라는 역할(role)과 함께, 생성될 대화의 목적과 제약 조건을 명확히 제시. 공통으로 사용하는 시스템 프롬프트에는 다음 요소가 포함.
●	역할 정의: "당신은 15년 경력의 금융 범죄 수사 전문가이자 음성 피싱 탐지 시스템 개발자입니다."
●	출력 언어: "대화 텍스트를 한국어로 출력해주세요."
●	대화 유형별 규칙: 각 시나리오(대출빙자형·메신저 피싱형·택배사칭형·기관사칭형)에 대해 "한 대화에는 한 가지 유형만 포함시킬 것" 등 일관된 규칙을 제시
●	대화 구성: "3~10문장(또는 8~12문장, 13~15문장)으로 구성하고, 피싱범(0)과 피해자(1)가 번갈아가며 대화할 것"
●	이름 사용: 모든 대화에서 고정 이름 'OOO' 사용
●	다양성·중복 방지: "대화를 현실적이고 자연스럽게 만들며 다양성을 확보하고, 이전에 생성된 대화와 중복을 피할 것"
●	출력 형식: "phishing_001,loan fraud,0,문장…"처럼 CSV 무헤더 형식으로 결과를 반환
실제 프롬프트 활용 시에는 OpenAI API 비용 절감을 위해 위의 한글 지침을 영어로 번역하여 프롬프트를 설계. 이후 사용자 프롬프트(user prompt)에서는 동적 변수(대화 수 n, 시작 인덱스 start_index, 시나리오 유형)를 주입하여 호출 시마다 다른 명령을 전달. 

예를 들어:
text
1)	5개의 메신저 피싱 음성 피싱 시나리오를 생성해주세요. 파일명은 phishing_006부터 순차적으로 부여해주세요.

결론: 시스템 프롬프트로 전체 룰을 고정하고, 사용자 프롬프트로 매 배치마다 필요한 구체 조건을 전달함으로써 프롬프트의 재사용성과 유지보수성을 확보.

4.1.3. gpt-4o 선택 이유 및 장점
이 데이터 생성 파이프라인에서는 gpt-4o를 최종 선택하였으며, 그 이유는 다음과 같습니다.
●	비용 효율성: gpt-4o는 동일 작업량 기준 기존 gpt-4 및 gpt-3.5-turbo 대비 API 호출 비용이 대폭 낮아, 대규모 시나리오 데이터셋 생성에 필요한 경제성을 제공합니다.
●	우수한 성능: 최신 gpt-4o는 자연스러운 한국어 문장 생성 능력과 일관된 대화 맥락 유지, 현실성 있는 시나리오 구조화 등에서 gpt-3.5 및 구 버전 gpt-4보다 더 뛰어난 결과를 보입니다.
●	고속 응답: 동적 배치 및 반복 호출을 요하는 작업 환경에서, gpt-4o는 빠른 응답성과 안정성 덕분에 전체 데이터 생성 과정을 단축할 수 있습니다.
즉, 비용과 성능을 모두 고려할 때 gpt-4o 사용이 최적임을 확인할 수 있었으며, 이는 실제 데이터 생산 과정에서 중요한 실질적 장점으로 작용하였습니다.

●	대화 흐름의 현실성 (예: [image:2]의 가족지인사칭 예시)
●	발화자(0=피싱범, 1=피해자) 역할 및 CSV 무헤더 형식 준수
●	고정 이름 ‘OOO’ 사용 일관성
검토 결과, 3% 미만의 문장 어색함이 발견되었으며 해당 문장만 선별 수정 후 재검증을 완료하였다.
넷째, 자동화 검증 파이프라인 및 승인 기준을 운영하였다.
●	중복 파일명·start_index 연속성·CSV 구문 분석 에러율 0% 달성
●	전체 대화 중 97% 이상이 품질 기준(제약 준수·자연스러움)을 충족
●	검증 실패율 3% 초과 시 해당 배치 전체를 재배치하도록 설정
모든 검증 로그는 별도 대시보드에 실시간 기록되며, API 호출 시마다 자동 보고서가 생성된다.
이와 같은 다단계 검증 절차를 통해 데이터 품질을 실무 수준에서 확보하였으며, 해당 원칙을 이후 모든 배치에도 일관되게 적용함으로써 음성 피싱 탐지 모델 학습에 최적화된 데이터셋을 유지 관리하고 있다.
 
4.2. 데이터 증강: 역번역(Back-Translate)

4.2.1. 증강 목표 및 프롬프트 설계계
보이스피싱 탐지 모델의 일반화 성능을 높이고, 실제 범죄 시나리오에 가까운 다양성을 확보하기 위해 LLM을 활용한 역번역 기반 데이터 증강을 수행하였다. 증강의 주요 목적은 원본 데이터를 의미는 유지하되 표현을 다양화하여 모델이 보다 넓은 문맥과 문장 구조에 대응할 수 있도록 하는 데 있다.
이를 위해 다음과 같은 세부 전략을 수립하였다:
●	다국어 기반 역번역 수행: 영어, 중국어, 독일어를 중간 번역 언어로 설정하여 원문의 의미를 유지하면서도 다양한 표현 방식으로 재구성
●	보이스피싱 유형별 범죄 통계에 따른 비율 반영: 증강된 데이터의 비중이 실제 범죄 유형 분포를 따르도록 조정함 (예: 기관사칭형 약 53%, 대출빙자형 약 24%, 메신저피싱형 7% 등)
●	총 6,000개의 증강 데이터를 생성하여 기존 데이터와 병합하되, 중복 제거 및 품질 검증 절차를 통해 최종 데이터셋을 구성함
데이터 증강은 다음과 같은 실행 흐름으로 구성되었다:
1.	증강 대상 문장 선별: 원본 보이스피싱 데이터셋에서 증강이 필요한 대표 문장을 추출
2.	다국어 역번역 수행: 각 문장에 대해 영어, 중국어, 독일어 3가지 언어를 중간 매개 언어로 설정하여 순차적으로 역번역 수행
3.	재구성된 한국어 문장 수집: OpenAI GPT API를 활용하여 번역된 문장을 다시 자연스럽고 현실적인 표현으로 생성
4.	중복 제거 및 정제: 기존 문장과의 의미 유사도 검사를 통해 중복 제거, 글자 수와 문장 품질 필터링 절차를 수행
5.	병합 및 라벨링: 기존 보이스피싱 유형 레이블(phishing_type)을 유지한 채 최종 데이터셋으로 통합
이러한 절차를 통해 총 6,000개의 증강 문장을 확보하였으며, 각 문장은 카테고리 비율과 품질 기준을 충족하도록 관리되었다.

 
4.2.2. 프롬프트 엔지니어링
프롬프트 설계는 시스템 프롬프트와 사용자 프롬프트로 분리 되며 다음과 같은 구성으로 설계되었다:
●	시스템 프롬프트: "너는 한국 보이스피싱 탐지 시스템 프로젝트의 데이터 증강 전문가야. 사용자가 주는 한국어 문장은 보이스피싱 사례 텍스트야. 너의 임무는 이 문장을 먼저 지정된 언어(중국어, 영어, 독일어)로 자연스럽게 번역한 뒤, 다시 한국어로 자연스럽고 다양하게 재구성해주는 거야. 단, 원래 문장의 의미와 맥락은 유지하되 표현을 바꾸고, 자연스럽고 실제 통화처럼 들리도록 만들어야 해. 최종 출력은 오직 자연스럽고 일상적인 한국어 문장 하나만 포함해야 해."
●	사용자 프롬프트: "다음 문장을 중국어로 번역한 뒤, 다시 자연스럽고 실제 대화처럼 들리게 한국어로 재번역해줘. 출력에는 반드시 한국어 문장만 포함돼야 해. 중국어 단어, 설명, 번역 과정은 절대 포함하지 마: '[문장 입력]'"
이러한 프롬프트 설계를 통해 출력의 일관성과 자연스러움을 동시에 확보하였다.

5. 최종 학습 데이터셋 구성 및 평가
5.1. 1차 모델 통합 데이터셋 
1) 보이스피싱 데이터셋 구성 비율 확인
 
- 최종 구성: 수집 데이터 전처리 후 데이터셋 12.8%(767건), LLM 역번역 증강 데이터셋65.9% (3954건), LLM 프롬프트 생성 데이터셋21.3% (1279건)
- 정보 보안 정책으로 인해 공개된 데이터셋의 양이 적어 생성 및 증강 데이터의 비율이 높음. 
- 수집 데이터의 통계와 신뢰있는 기관의 자료를 기반으로 생성하여 신뢰도를 높임. 


2) 통합 데이터셋 차원 및 구조적 무결성 확인

 	 

- 데이터 차원: 총 12,000개의 행과 6개의 열로 구성되어 있음.
- 데이터 구조: file_id(object), text(object), phishing_type(object), is_phishing(int)
- 결측치: phishing type 컬럼의 결측치 6000건은 일반 대화는 피싱 유형이 없기 때문에, 데이터 오류가 아니라 의도된 값이며, 이는 '정상 대화' 클래스를 구분하는 자연스러운 특징으로 활용할 수 있음. 


3) 통합 데이터셋 스키마 및 데이터 타입 유효성 검사
 
- 컬럼 스키마 일치 확인
- 데이터 타입 정확성 확인
- 유형별 허용 값 확인


5.1.2. 데이터 품질 검증

1) 중복 데이터 확인
 - 검증 목적: 모델 학습 시 동일한 데이터가 중복으로 사용되어 특정 패턴에 과적합(Overfitting)되는 것을 방지. 데이터셋에 포함된 모든 샘플의 고유성을 보장.
- 검증 방법: Pandas 라이브러리를 활용하여 데이터셋 전체의 text 컬럼을 기준으로, 내용이 완전히 일치하는 중복 데이터가 존재하는지 확인.
- 결과 및 결론: 중복 데이터 0건. 데이터 수집, 생성 및 증강 과정에서 중복이 효과적으로 제어되어 데이터셋의 모든 대화가 고유한 샘플로서의 가치를 가짐.


2) 논리적 구조 라벨링 적합성 확인 
- 검증 목적: 메인 라벨인 is_phishing과 서브 라벨인 phishing_type 간의 논리적 일관성을 검증하여, 라벨링 시스템의 신뢰도를 확보.
- 검증 방법: 논리적으로 발생해서는 안 되는 두 가지 오류 시나리오를 정의, 해당 사례가 데이터셋에 존재하는지 확인.
●	오류 시나리오 1: is_phishing 값이 0(정상 대화)임에도 불구하고, phishing_type에 특정 유형(예: '기관사칭형')이 할당된 경우
●	오류 시나리오 2: is_phishing 값이 1(피싱 대화)임에도 불구하고, phishing_type이 누락(결측치)된 경우
- 결과 및 결론: 위 두 오류 시나리오에 해당하는 데이터는 0건으로 라벨링 구조의 논리적 모순이 발견되지 않음. 데이터셋의 라벨링 체계가 명확한 규칙에 따라 일관성 있게 적용되었음을 확인. 모델이 각 클래스의 특성을 혼동 없이 학습할 수 있는 구조를 갖춤.


3) 데이터 이상치 탐지
  
- 텍스트 길이의 통계적 이상치는 총 894건이 발견. 이상치의 유형별 분포를 분석한 결과, 전체 이상치 중 기관사칭형(577건)과 대출빙자형(290건)이 약 97%(총 867건)를 차지하는 것으로 나타남. 이는 두 유형이 피해자를 설득하고 신뢰를 얻기 위해 다른 유형보다 상대적으로 긴 대화를 유도하는 수법적 특성과 일치.


4) 개인정보보호 및 윤리적 고려사항 
- 개인정보 처리: 본 프로젝트에서 사용된 모든 원본 데이터(AIHub, 금융감독원 등)는 수집 단계에서부터 이름, 연락처, 주소 등 주요 개인 식별 정보(PII)가 사전에 마스킹 처리된 데이터임을 확인.
- 자체 검증: 데이터셋의 일부를 샘플링하여 추가적인 개인정보 노출이 없는지 2차 검증을 완료했으며, 이를 통해 데이터의 익명성이 보장됨을 확인.


5.1.3. 클래스별 분포 및 특성 분석 

1) 보이스 피싱 대화, 일반 대화 클래스 분포 확인

  

-클래스 균형 맞추기: 일반 대화, 보이스피싱 대화 1:1 비율. 검증시 층화추출 하기에 용이함.


2) 피싱 유형(phishing_type)별 분포 확인
 
- 현 보이스 피싱 유형별비율(출처: 경찰청)과 맞춘 분포이기 때문에 데이터 불균형이 있음.
- 피싱 유형 클래스별 불균형 보완을 위해 토큰화 진행후 n-gram 시행. (추후 SMOTE 기법 적용하여 오버샘플링 가능성 있음. )


5.1.4. 종합 품질 평가 및 결론
1) 총평 
- 본 1차 통합 데이터셋은 체계적인 수집, 정제, 증강 및 검증 파이프라인을 거쳐 구축. 분석 결과, 일부 통계적 특성을 인지하고 관리한다는 전제하에 머신러닝 모델 학습 초기 단계에 사용하기에 충분한 품질을 확보한 것으로 평가.

2) 주요 품질 확보 항목
- 클래스 간 균형 확보: 보이스피싱과 일반 대화 데이터의 비율을 1:1로 구성, 모델이 특정 클래스에 편향되지 않고 균형 잡힌 학습을 수행할 수 있는 기반 마련.
- 데이터 구조적 무결성: 전체 데이터셋의 스키마, 데이터 타입, 결측치(의도된 결측 포함)를 검증한 결과, 데이터가 일관성 있는 구조를 가지며 기술적 오류가 없음을 확인.
- 현실 세계 특성 반영: 특정 유형에서 발견된 통계적 이상치를 제거하지 않고 포함함으로써, 실제 보이스피싱 수법의 다양한 특성(예: 긴 설득 과정)을 모델이 학습할 수 있도록 데이터의 현실성을 높임.

3) 고려사항 및 한계점
- 데이터 출처의 편중성: 데이터셋의 약 87%가 LLM을 통해 생성 및 증강된 데이터로 구성. 이는 정보보안 정책상 원본 데이터 확보의 한계에 기인한 것으로, 신뢰도 높은 기관의 자료를 기반으로 생성하여 편향을 최소화하고자 노력함.
- 피싱 유형 내 클래스 불균형: 피싱 유형(phishing_type) 분포는 실제 범죄 통계를 반영하여 의도적으로 불균형하게 구성. 이는 현실성을 높이는 장점이 있으나, 소수 유형(예: 택배사칭형)에 대한 모델의 탐지 성능이 저하될 수 있는 잠재적 리스크를 내포함. (이는 5.1.2에서 언급된 n-gram, SMOTE 등의 기법으로 보완될 예정.)

 
6. 문제점 및 개선 방안 

- 일부 LLM 라벨 오류: 수작업 검수 비중 확대 필요

- 최신 유형 반영 필요: 정기적 데이터 수집 일정 수립
