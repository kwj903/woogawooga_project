## 1. 문서 개요
본 문서는 보이스피싱 판단 AI의 전체 요구사항을 정의하기 위한 문서로, 시스템의 기능적/비기능적 요구사항, 구현 범위, 시스템 아키텍처 및 이해관계자 정보를 포함한다.

## 2. 시스템 배경 및 목적

### 2.1 배경
최근 지능화, 고도화되는 보이스피싱 범죄로 인한 사회적 피해 규모가 매년 증가하고 있으며, 특히 디지털 취약 계층의 피해가 심각한 수준이다. 기존의 스팸 차단 앱이나 번호 기반 방식은 신종 사기 수법을 탐지하는 데 한계가 있다.

### 2.2 목적
본 프로젝트는 통화의 '맥락'을 분석함으로써 기존 방식으로는 탐지하기 어려운 보이스피싱을 판별하여 사용자의 금융 자산을 보호하고, 범죄에 노출될 수 있다는 불안감을 해소하여 심리적 안정감을 제공하는 것을 목표로 한다.
## 3. 시스템 개요

### 3.1 구현 범위
본 프로젝트는 Django 프레임워크 기반의 웹 환경에서 사용자가 업로드한 음성 파일을 5단계 파이프라인(STT → 텍스트 전처리 → 1차 ML → 2차 DL → LLM)을 통해 분석하여 보이스피싱 여부를 판별하는 서비스이다.

웹 애플리케이션은 SPA 방식으로 구현되어 파일 업로드부터 분석 결과 확인까지의 전 과정을 하나의 페이지에서 처리하며, WebSocket을 통한 실시간 진행률 표시, 별도의 통계 페이지(/statistics/), 사용자 피드백 시스템, 포괄적 로깅 시스템을 제공한다.

### 3.2 시스템 플로우
시스템의 핵심 처리 플로우는 5단계 파이프라인으로 구성된다:

1. **1단계: STT 변환** - VITO API를 통해 음성 파일을 텍스트로 변환
2. **2단계: 텍스트 전처리** - KiWi 형태소 분석기를 사용하여 NNG, NNP, VV, VA 품사 추출 및 전처리
3. **3단계: 1차 ML 분석** - Stacking Classifier 모델로 초기 분류 수행. 임계값 0.5 기준으로 명확한 케이스는 즉시 판별하고, 애매한 케이스는 '보류'로 분류
4. **4단계: 2차 DL 분석** - 보류 케이스에 대해 EnsemblePhishingDetector(PyTorch 기반)가 정밀 분석 수행
5. **5단계: LLM 설명 생성** - GPT-4o를 통해 보이스피싱 유형 분류 및 사용자 친화적 경고 메시지 자동 생성

전체 과정은 WebSocket을 통해 실시간으로 진행률이 업데이트되며, 각 단계별 상세 로그가 기록된다. 각 단계는 순차적으로 진행되고, ProcessdFile, InferenceResult, AnalysisResult, SystemLog 테이블에 결과가 저장된다.

## 6. 품질 관리 요구사항

### 6.1 품질 검사 절차
- **자가점검**: 데이터 가공(라벨링) 완료 후, 초기 작업자가 아닌 다른 팀원이 교차 검토를 수행하여 라벨링의 일관성과 정확성을 2차로 검증한다.
- **도구 검사**: 정기적으로 자동화된 스크립트를 실행하여 데이터 포맷의 유효성, 필수 항목의 누락 여부, 라벨 값의 범위를 자동으로 검사하여 오류를 식별한다.

### 6.2 단계별 품질 목표 및 검사 기준

#### 데이터 품질 목표
- **라벨링 정확도**: 100%
- **필수 항목 누락률**: 5% 이하

#### 1차 ML 모델 기준: Recall (재현율)
1차 모델은 보이스피싱을 놓치지 않는 것이 가장 중요. FN(False Negative)를 최소화해야 2차 모델에게 충분한 정보를 넘길 수 있음.

#### 2차 DL 모델 기준: F1 Score (Precision과 Recall의 균형)  
2차 모델은 판단 유보된 애매한 케이스를 정확하게 판별해야 하므로, 정밀도와 재현율 모두 중요함. 보조지표로 Confusion Matrix 분석, PR Curve 또는 ROC-AUC 활용

#### 통합 시스템 목표
- **최종 정확도(Accuracy)**: 90% 이상
- **False Negative Rate**: 최소화  
- **시스템 가용성**: 99.9% 이상

## 8. 제약 사항 및 기술적 고려사항

### 8.1 데이터 및 보안 제약
- 개인정보보호 이슈로 인한 데이터 부족은 추출 및 생성하여 보완
- 사용자 데이터는 암호화하여 저장하고 개인정보 보호법을 준수  
- 업로드된 음성 파일은 분석 완료 후 자동 삭제 (보안 강화)

### 8.2 파일 및 시스템 제약
- **파일 업로드 크기 제한**: 최대 50MB (음성 파일 기준)
- **지원 파일 형식**: AMR, MP3, WAV, M4A
- **브라우저 호환성**: Chrome, Firefox, Safari, Edge 최신 버전
- **웹 기반 구현으로 인한 실시간 통화 분석 기능은 제외**

### 8.3 외부 API 의존성
- **VITO API**: STT 변환을 위한 필수 서비스
- **GPT-4o API**: LLM 설명 생성을 위한 필수 서비스  
- **API 장애 시 백업 전략**: 목업 데이터 활용으로 서비스 연속성 보장

### 8.4 성능 및 확장성 제약
- **동시 처리 가능한 분석 요청 수**: 서버 리소스에 따라 제한
- **MySQL 데이터베이스 연결 제한**: 동시 연결 수 고려 필요
- **모델 로딩 시간**: 앱 시작 시 ML/DL 모델 초기화 시간 소요
