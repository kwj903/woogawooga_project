## 1. 문서 개요

### 1.1 목적
본 문서는 Django 4.x + Django Channels 기반 웹 애플리케이션의 데이터 요구사항, 데이터 플로우, 저장 방식, 보안 요구사항 등을 정의하여 데이터 관리 및 유지보수의 기준을 제시한다.

### 1.2 적용 범위
- **Django 5.2 기반** 웹 애플리케이션의 전체 데이터 라이프사이클
- **4단계 AI 파이프라인**: STT → ML(1차) → DL(2차) → LLM(최종판단)
- **다중 API 통합**: VITO STT API, OpenAI GPT API, 다중 AI 모델 앙상블
- **Django Channels 기반** WebSocket 실시간 통신
- **7개 Django 모델**: ProcessdFile, InferenceResult, ModelRegistry, Feedback, VoicePhishingSystemLog, SystemLog, AnalysisResult
- **MySQL/SQLite 듀얼 DB**, Django Media 파일 시스템, 사용자 피드백 시스템

### 1.3 데이터 개요 및 주요 데이터 자산

#### 1.3.1 입력 데이터 (실제 구현 기준)
- **음성 파일**: .mp3, .wav, .m4a 형식 (최대 50MB, UUID 파일명으로 저장)
- **사용자 피드백**: 예측결과 정확성(Y/N), 의견내용(선택적)
- **실시간 업로드**: Django FileField + 파일 검증

#### 1.3.2 처리 데이터 (4단계 파이프라인)
- **1단계 STT**: VITO API → transcript (TextField)
- **2단계 ML**: Random Forest, Logistic Regression → prcs_cont_1 (JSONField)
- **3단계 DL**: KoBERT, mBERT 앙상블 → prcs_cont_2 (JSONField) 
- **4단계 LLM**: GPT API → 피싱유형명, 경고내용 생성
- **데이터베이스 트랜잭션**: 모든 결과 원자적 저장

#### 1.3.3 출력 데이터 (Django 모델 기준)
- **InferenceResult**: ml_rslt_cd('0'/'1'/'보류'), prdt_scr(0.000-1.000), phsh_tp_nm, warn_cn
- **AnalysisResult**: is_phishing(Boolean), confidence(Float), warning_message(Text)
- **시스템 로깅**: VoicePhishingSystemLog(상세), SystemLog(범용)
- **통계 대시보드**: 일일 분석 건수, 피싱 탐지율, 모델 성능 지표

## 3. 데이터 처리 플로우

### 3.1 4단계 AI 파이프라인 데이터 처리 (실제 구현)
| 단계 | 입력 데이터 | 처리 방식 | 출력 데이터 | Django 모델 저장 |
|------|------------|----------|------------|---------------|
| **1단계: STT** | 업로드 음성파일 (.mp3, .wav, .m4a, ≤50MB) | VITO STT API → UUID 파일명 저장 | transcript | ProcessdFile.transcript |
| **2단계: ML** | STT 전사 텍스트 | Random Forest + Logistic Regression + TF-IDF | ML 예측결과, 신뢰도 | ProcessdFile.prcs_cont_1 (JSON) |
| **3단계: DL** | 전처리된 텍스트 | KoBERT + mBERT 앙상블 → PyTorch 추론 | DL 정밀분석 결과 | ProcessdFile.prcs_cont_2 (JSON) |
| **4단계: LLM** | ML+DL 종합결과 | GPT API → 피싱유형 + 경고메시지 생성 | 최종 판단, 설명 | InferenceResult 테이블 |
| **결과저장** | 전체 파이프라인 결과 | Django ORM 트랜잭션 (원자성) | 통합 분석 데이터 | AnalysisResult (UI 호환) |
| **피드백** | 사용자 평가 | 웹 UI → AJAX → Django views | 사용자 검증 데이터 | Feedback 테이블 |

### 3.2 실제 데이터 플로우 (Django 기준)

```python
# 실제 구현 순서
1. 파일 업로드 → ProcessdFile 생성 (ocrn_no 생성)
2. STT API 호출 → transcript 저장
3. ML 모델 추론 → prcs_cont_1 업데이트  
4. DL 모델 추론 → prcs_cont_2 업데이트
5. LLM API 호출 → InferenceResult 생성
6. UI 호환성 → AnalysisResult 생성
7. 사용자 피드백 → Feedback 생성
8. 로깅 → VoicePhishingSystemLog + SystemLog
```

### 3.2 실시간 데이터 업데이트 (WebSocket)
| 진행 단계 | WebSocket 메시지 | 프론트엔드 업데이트 | 데이터 상태 |
|----------|------------------|---------------------|----------|
| STT 진행중 | `{"step": 1, "progress": 25, "message": "음성 변환 중..."}` | 진행률 바 업데이트 | 파일 정보 저장됨 |
| 전처리 중 | `{"step": 2, "progress": 50, "message": "텍스트 분석 중..."}` | 상태 메시지 변경 | 전처리 결과 저장됨 |
| 1차 분석 | `{"step": 3, "progress": 75, "message": "AI 분석 중..."}` | 분석 단계 표시 | 추론 결과 생성됨 |
| 분석 완료 | `{"step": 4, "progress": 100, "message": "분석 완료"}` | 결과 화면 전환 | 최종 결과 완료 |

#### 6.2.1 보이스피싱 여부(is_phishing): 이진 분류
| 클래스(라벨) | 설명 |
|-------------|------|
| 0 | 일반 대화 |
| 1 | 보이스피싱 대화 |

#### 6.2.2 보이스피싱 화자(speaker) 분류
| 클래스(라벨) | 설명 |
|-------------|------|
| 0 | 보이스피싱 범죄자 |
| 1 | 피해자 |

#### 6.2.3 보이스피싱 유형(phishing_type): 다중 클래스
클래스 종류:
- 기관사칭형
- 대출빙자형
- 메신저피싱형
- 가족지인사칭형
- 투자권유형
- 세금환급형
- 콜백스미싱형

#### 6.2.4 데이터셋 분할
- **분할 비율**: 학습(Training) 80% / 검증(Validation) 10% / 테스트(Test) 10%
- **분할 방법**: 계층적 샘플링 (Stratified Sampling)
- **클래스 비율**: 피싱 1 : 일반 1
