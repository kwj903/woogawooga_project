## 2. 상세 화면 정의 (단일 페이지 애플리케이션)

### 2.1 SPA 메인 페이지: templates/voice_phishing/index.html
- **URL**: http://localhost:8000/
- **목적**: 단일 페이지 애플리케이션으로 4개 화면을 JavaScript로 전환
- **JavaScript 클래스**: VoicePhishingDetector (main.js)

**전체 구성 요소**:
- **헤더 (고정)**
  - 방패 아이콘 + "woogawooga" 제목
  - 브레드크럼: 홈 아이콘 + "업로드" (현재 단계 표시)
- **메인 콘텐츠 영역** (4개 화면 중 1개씩 표시)
  - upload-screen: 업로드 화면 (기본 표시)
  - analysis-screen: 분석 진행 화면 (hidden)
  - result-screen: 결과 화면 (hidden)
  - error-screen: 오류 화면 (hidden)

### 2.2 SPA-01: 업로드 화면 (upload-screen)
- **상태**: 기본 표시 상태 (default)
- **목적**: 음성 파일 업로드 시작점

**구성 요소**:
- **카드 헤더**
  - 제목: "보이스피싱 판별 시스템"
  - 부제: "음성 파일 업로드"
- **업로드 섹션**
  - 파일 아이콘 + "음성 파일 업로드" 제목
  - 지원 포맷 안내: "※ 지원 포맷: AMR, MP3, WAV, M4A (최대파일용량: 50MB)"
  - 드롭 존: 업로드 아이콘, "파일을 선택하거나 여기에 드래그하세요", "파일 선택" 버튼
  - 선택된 파일 정보: 파일명, 크기(MB) 표시 (조건부, hidden 클래스로 제어)
- **버튼 영역**
  - "분석 시작" 버튼 (파일 선택 시 활성화, disabled 속성으로 제어)

**기능 명세**:
- 드래그앤드롭 파일 업로드 (데스크톱 환경)
- 터치 디바이스 지원 (모바일 최적화)
- 파일 형식 검증 (mp3, wav, amr, m4a, audio/*)
- 파일 크기 검증 (50MB 제한)
- 화면 회전 및 모바일 키보드 대응
- "분석 시작" 버튼 클릭 시 분석 진행 화면으로 전환

### 2.3 SPA-02: 분석 진행 화면 (analysis-screen)
- **상태**: JavaScript로 전환 (hidden → visible)
- **목적**: 분석 진행 상태 실시간 표시

**구성 요소**:
- **카드 헤더**
  - 제목: "보이스피싱 판단 시스템"
  - 부제: "음성 파일 분석"
- **진행률 표시**
  - 진행률 바: progress-container > progress-bar > progress-fill (0% → 100%)
  - 진행률 텍스트: "분석 진행률: X%" (실시간 업데이트)
- **5단계 진행 표시** (analysis.html 별도 템플릿)
  - STT 변환, 1차 ML 분석, 2차 DL 분석, LLM 메시지 생성 단계별 아이콘
  - 각 단계별 완료/진행 중 상태 표시 (체크 아이콘, 스피너)
  - 전체 진행률 바 및 현재 상태 메시지

**백엔드 5단계 분석 파이프라인**:
1. **STT 변환** (VITO STT API) - 음성을 텍스트로 변환
2. **텍스트 전처리** (KiWi) - 형태소 분석 및 토큰화
3. **1차 ML 분석** (Stacking Classifier) - 키워드 기반 초기 분류
4. **2차 DL 분석** (PyTorch Ensemble) - 보류 케이스 정밀 분석
5. **LLM 메시지 생성** (GPT-4o) - 맞춤형 경고 메시지 생성

**기능 명세**:
- **WebSocket 통신**: ws://domain/ws/analysis_progress/{task_id}/
- **시뮬레이션 기반 진행**: 프론트엔드 시뮬레이션 + 백엔드 실제 분석 병렬 처리
- **실시간 진행률 업데이트**: 5단계별 진행 상황 표시
- **프론트엔드 로깅**: 클라이언트 이벤트 백엔드 전송
- **분석 완료 시**: 결과 화면으로 자동 전환
- **오류 발생 시**: 오류 화면으로 전환

### 2.4 SPA-03: 결과 화면 (result-screen)
- **상태**: JavaScript로 전환 (분석 완료 시)
- **목적**: 분석 결과 표시 및 피드백 수집

**구성 요소**:
- **카드 헤더**
  - 제목: "분석 결과"
  - 부제: "음성 파일 분석이 완료되었습니다"
- **결과 정보**
  - "■ 최종 결과:" 정상/보이스피싱
  - "■ 유형:" 기관사칭형 등 (피싱인 경우에만)
  - "■ 경고 메시지:" 분석 결과에 따른 메시지
- **피드백 섹션** (feedback-section)
  - "■ 분석 결과가 정확한가요?"
  - 라디오 옵션: "정확함" / "부정확함" (name="feedback-accuracy")
  - 추가 의견 텍스트 영역 (textarea, placeholder 포함)
  - "피드백 제출" 버튼 (초기 disabled, 라디오 선택 시 활성화)
  - 피드백 상태 표시 영역 (성공/실패 메시지)
- **액션 버튼**
  - "다시 분석" 버튼: resetToUpload() 호출로 업로드 화면 복귀

**기능 명세**:
- **결과 표시**: 최종 판별 결과 (is_phishing), 피싱 유형 (phishing_type), 신뢰도 (confidence)
- **경고 메시지**: GPT-4o 생성 맞춤형 경고 메시지 (warning_message)
- **피드백 시스템**: 
  - 정확도 평가 (accurate/inaccurate)
  - 추가 의견 입력 (선택사항)
  - AJAX 통신 (/submit_feedback/)
  - Feedback 테이블 저장 (prp_no, rslt_id, ocrn_no, prdt_rslt_yn, wropn_cn)
- **상태 초기화**: resetFeedbackState() 함수로 피드백 섹션 완전 초기화
- **재분석 옵션**: resetToUpload() 호출로 업로드 화면 복귀

### 2.5 SPA-04: 오류 화면 (error-screen)
- **상태**: JavaScript로 전환 (오류 발생 시)
- **목적**: 분석 실패 시 오류 안내

**구성 요소**:
- **카드 헤더**
  - 제목: "분석 실패" (빨간색)
  - 부제: "분석 중 오류가 발생했습니다"
- **오류 정보**
  - 경고 아이콘 + "분석 오류"
  - 오류 메시지 표시
- **액션 버튼**
  - "재시도" 버튼: 같은 파일로 다시 분석
  - "새 파일 업로드" 버튼: 업로드 화면으로 돌아가기

**기능 명세**:
- 오류 상황 안내 (alert-error 스타일)
- 동적 오류 메시지 표시 (error-message ID)
- 재시도 기능: 동일 파일로 재분석 시도
- 새 파일 업로드: 완전 초기화 후 업로드 화면 복귀
- 오류 로깅 및 추적 시스템 연동

### 2.6 UI-05: 통계 페이지 (templates/voice_phishing/statistics.html)
- **URL**: http://localhost:8000/statistics/
- **목적**: 시스템 사용 통계 대시보드

**구성 요소**:
- **헤더**
  - 방패 아이콘, "woogawooga - 통계"
  - 브레드크럼: "홈 / 통계" ({% url 'voice_phishing:index' %} 링크)
- **통계 카드**
  - 카드 헤더: "분석 통계", "시스템 사용 현황"
  - 통계 그리드 (4개):
    - 총 분석 건수: {{ total_analyses }}
    - 보이스피싱 탐지: {{ phishing_count }} (phishing 클래스, 빨간색)
    - 정상 통화: {{ normal_count }} (normal 클래스, 녹색)

**기능 명세**:
- **데이터 소스**: AnalysisResult 테이블 집계
- **실시간 통계**: views.py statistics() 함수에서 동적 계산
- **템플릿 변수**: total_analyses, phishing_count, normal_count, phishing_rate
- **반응형 레이아웃**: stats-grid CSS 클래스
- **네비게이션**: 브레드크럼으로 홈 페이지 연결

## 5. 시스템 사용 방법

### 5.1 시스템 접속 및 시작
1. http://localhost:8000/ 접속
2. 접속하면 바로 업로드 화면이 표시됩니다
3. 별도의 메인 페이지나 로그인 과정이 없습니다

### 5.2 음성 파일 업로드 및 분석 (1단계)
**화면 구성**:
1. 화면 상단에 "woogawooga" 제목과 "음성 파일 업로드" 안내 표시

**파일 업로드 방법** (2가지):
- **방법1**: "파일 선택" 버튼 클릭 후 음성 파일 선택
- **방법2**: 파일을 드래그앤드롭 영역에 직접 드래그

**지원 파일 형식 및 통화 길이**:

| 파일 형식 | 확장자 | 최대 크기 | 예상 통화 길이 (품질별) |
|----------|--------|-----------|------------------------|
| AMR | .amr | 50MB | 약 400-500분 (저품질 압축) |
| MP3 | .mp3 | 50MB | 약 60-120분 (일반 품질 128kbps 기준) |
| WAV | .wav | 50MB | 약 4-6분 (고품질 무압축) |
| M4A | .m4a | 50MB | 약 80-150분 (중간 품질 압축) |

**분석 시작**:
4. 파일 선택 후 "분석 시작" 버튼 활성화
5. "분석 시작" 버튼 클릭 시 분석 진행 화면으로 자동 전환

### 5.3 분석 진행 확인 (2단계)
1. 화면이 자동으로 "음성 파일 분석" 단계로 전환
2. 진행률 바와 분석 상태 메시지 표시
3. "분석을 준비하고 있습니다..." → "분석 진행 중..." 등 상태 업데이트
4. 분석 완료 시 자동으로 결과 화면으로 전환

### 5.4 분석 결과 확인 (3단계)
**주요 결과 정보**:
1. "분석 결과" 화면에서 다음 정보 확인:
   - 최종 분석 결과 (정상/보이스피싱)
   - 피싱 유형 (기관사칭형, 대출사기형 등)
   - 경고 메시지

**피드백 제출**:
2. 피드백 제출:
   - "분석 결과가 정확한가요?" 질문에 라디오 버튼으로 응답
   - 추가 의견 텍스트 입력 (선택사항)
   - "피드백 제출" 버튼으로 의견 전송

**다음 작업**:
3. 다음 작업:
   - "다시 분석" 버튼: 새로운 파일 분석을 위해 업로드 화면으로 돌아가기

### 5.5 오류 처리 (4단계 - 조건부)
1. 분석 중 오류 발생 시 "분석 실패" 화면 표시
2. 오류 메시지 확인
3. "재시도" 또는 "새 파일 업로드" 버튼으로 다시 시작

### 5.6 통계 페이지 이용 (별도 페이지)
- **주소**: /statistics/ (직접 URL 입력으로 접속)
- **확인 가능 정보**:
  - 총 분석 건수
  - 보이스피싱 탐지 건수
  - 정상 통화 건수
  - 피싱 탐지율

## 6. 기술적 특징 및 구현 세부사항

### 6.1 단일 페이지 애플리케이션 (SPA)
- 하나의 HTML 파일에 4개 화면 모두 포함 (index.html)
- JavaScript 클래스 기반 상태 관리 (VoicePhishingDetector)
- CSS hidden 클래스를 통한 화면 전환 (showScreen 메서드)
- 페이지 새로고침 없는 부드러운 전환

### 6.2 백엔드 아키텍처
- **Django 4.x + Django Channels**: REST API + WebSocket
- **5단계 분석 파이프라인**: STT → 전처리 → 1차ML → 2차DL → LLM
- **WebSocket 실시간 통신**: Django Channels, InMemoryChannelLayer
- **다중 AI 모델 통합**: VITO API, Stacking Classifier, PyTorch Ensemble, GPT-4o
- **포괄적 로깅 시스템**: Python logging, 파일/DB/콘솔 동시 출력
- **데이터베이스**: MySQL, 7개 모델 테이블
- **환경 설정**: .env 파일, 환경변수 관리

### 6.3 상태 관리 및 사용자 경험
- **파일 상태 관리**: 드래그앤드롭, 파일 검증, 업로드 상태 표시
- **분석 진행률**: WebSocket 기반 실시간 5단계 진행 표시
- **화면 전환**: showScreen() 메서드로 CSS hidden 클래스 토글
- **피드백 시스템**: resetFeedbackState() 함수로 완전 초기화
- **버튼 상태**: disabled 속성 동적 처리, 중복 실행 방지
- **시뮬레이션**: 프론트엔드 진행 시뮬레이션 + 백엔드 실제 분석 병렬

### 6.4 모바일 최적화
- 터치 디바이스 감지 및 대응
- 드래그앤드롭 대신 클릭 기반 파일 선택 (모바일)
- 화면 회전 및 키보드 대응 이벤트
- 반응형 레이아웃 (viewport 메타 태그)

## 8. 분석 결과 이해하기

### 8.1 분석 결과 해석
- **정상 통화**: 보이스피싱 위험이 낮은 일반적인 통화
- **보이스피싱**: 사기 전화로 판별된 위험한 통화

### 8.2 신뢰도 해석

| 신뢰도 범위 | 해석 | 권장 조치 |
|------------|------|-----------|
| 0.0 ~ 0.3 | 낮은 신뢰도 | 추가 확인 권장 |
| 0.4 ~ 0.6 | 보통 신뢰도 | 주의 깊은 검토 |
| 0.7 ~ 0.8 | 높은 신뢰도 | 신뢰할 만한 결과 |
| 0.9 ~ 1.0 | 매우 높은 신뢰도 | 높은 정확도 |

### 8.3 주요 보이스피싱 유형
- **기관사칭형**: 경찰, 검찰, 금융감독원 등 공공기관 사칭
- **대출사기형**: 대출 관련 허위 정보로 속이는 유형
- **금융사칭형**: 은행, 카드사 등 금융기관 사칭
- **기타**: 다양한 형태의 보이스피싱

### 8.4 주요 의심 키워드

| 카테고리 | 키워드 예시 |
|---------|-------------|
| 기관 사칭 | 경찰청, 검찰청, 금융감독원, 은행 등 |
| 금융 관련 | 계좌이체, 보안카드, OTP, 공인인증서 등 |
| 긴급성 조장 | 긴급, 즉시, 오늘 중, 지금 당장 등 |
| 개인정보 요구 | 주민번호, 계좌번호, 비밀번호 등 |

## 9. 문제 해결

### 9.1 일반적인 오류 및 해결방법

| 문제 상황 | 원인 | 해결방법 |
|-----------|------|----------|
| 파일 업로드가 안 됨 | 지원하지 않는 파일 형식 | MP3, WAV, AMR, M4A 형식의 파일을 사용하세요 |
| "파일 크기가 너무 큽니다" 오류 | 50MB를 초과하는 파일 | 파일 크기를 50MB 이하로 줄이거나 분할하세요 |
| "STT 처리에 실패했습니다" 메시지 | VITO API 오류 또는 음성 품질 문제 | 잠시 후 다시 시도하거나 더 명확한 음성 파일을 사용하세요 |
| 분석이 완료되지 않음 | 서버 처리 오류 | 페이지를 새로고침하고 다시 시도하세요 |
| 피드백 제출이 안 됨 | 네트워크 연결 문제 | 인터넷 연결을 확인하고 다시 시도하세요 |

### 9.2 브라우저 관련 문제
- **JavaScript가 비활성화된 경우**: 브라우저 설정에서 JavaScript 활성화
- **쿠키 차단된 경우**: 사이트의 쿠키 허용 설정
- **캐시 문제**: 브라우저 캐시 삭제 후 재접속

### 9.3 기술 지원
시스템 관련 문의나 버그 신고가 있으시면 개발팀에게 연락주세요.
- 상세한 오류 상황 및 재현 단계를 포함하여 문의해 주세요.

| 통화 길이 | 예상 분석 시간 | 비고 |
